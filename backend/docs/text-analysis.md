# Block 2: structured text analysis

Pure async component: caller-authorized `Evidence[]` → `TextAnalyzer` →
`GroqTextAnalyzer` → validated `AnalysisResult`. No database access, Note-ID
orchestration, HTTP endpoints, jobs, persistence or frontend changes.
Authentication, workspace access and evidence selection belong to the caller.

## Use

```python
from app.ai_engine.analysis import Evidence
from app.ai_engine.groq_adapter import create_text_analyzer

async with create_text_analyzer() as analyzer:
    result = await analyzer.analyze([
        Evidence(source_id="caller-owned-source", content="We decided to use PostgreSQL.")
    ])
```

Reuse the analyzer within one async lifecycle and close it on shutdown. The
factory is explicit, not called during API startup. Missing keys or invalid AI
configuration produce `AnalysisError(code="configuration")` while Notes remain
usable. Existing `LanguageModel.generate_insight` and `Extractor` are preserved;
`TextAnalyzer` is a separate narrow protocol.

## Provider contract

Official `groq` SDK (tested 1.7.0), `AsyncGroq`, Chat Completions:
`POST https://api.groq.com/openai/v1/chat/completions`.
Native SDK base URL is **https://api.groq.com**, without `/openai/v1`.
Only the official origin is allowed; tests inject an HTTP transport.

Every call sets the configured `openai/gpt-oss-20b` model, `reasoning_effort=low`,
`include_reasoning=false`, `stream=false`, `max_completion_tokens=2000` by default,
and `response_format={type: "json_schema", json_schema: {name: "text_analysis",
strict: true, schema: ...}}`. No tools, repair request, fallback or escalation.
Both model and effort are validated against the Block 2 profile. SDK retries
are fixed at zero. Redirects and environment proxy discovery are disabled.

All configuration is backend-only; see root `.env.example`:

| Setting | Default |
| --- | --- |
| `GROQ_API_KEY` | Required only when constructing the analyzer; hidden from settings repr |
| `GROQ_BASE_URL` | `https://api.groq.com` |
| `LLM_DEFAULT_MODEL` | `openai/gpt-oss-20b` |
| `LLM_DEFAULT_REASONING_EFFORT` | `low` |
| `LLM_MAX_INPUT_BYTES` | 4000 |
| `LLM_MAX_SOURCES` | 5 |
| `LLM_MAX_COMPLETION_TOKENS` | 2000 |
| `LLM_CONNECT_TIMEOUT_SECONDS` | 5 |
| `LLM_REQUEST_TIMEOUT_SECONDS` | 30 per transport operation |
| `LLM_DEADLINE_SECONDS` | 40 across request/response parsing |

The byte cap covers canonical compact UTF-8 JSON for the whole request,
including prompt, schema and options. It is a **size safety bound, not token
accounting or a guarantee of available free quota**. Oversized input is rejected,
never truncated or split. Prompt/schema overhead reduces usable evidence size.
Generated reasoning still uses completion budget even when not returned.
Prompt and schema version are code-owned `text-analysis-v1` constants; change
these with the corresponding implementation, not independently via environment.

## Structured output

```json
{
  "observations": [
    {
      "category": "decision",
      "text": "Use PostgreSQL.",
      "evidence": [{"source_id": "caller-owned-source", "quote": "We decided to use PostgreSQL."}]
    }
  ]
}
```

Categories: `fact`, `decision`, `intention`, `problem`, `entity`. All fields are
required and every object forbids extra properties. The Groq schema is generated
from the Pydantic contracts. Application validation also enforces at most 20
observations, nonblank text up to 500 characters, 1–5 references per observation,
and nonblank quotes up to 1000 characters. Empty `observations` is valid; empty
input/content is not. Input source IDs must be unique, nonblank, and at most
128 characters; IDs are never normalized or generated by the model.

References must use supplied source IDs and a substring of the corresponding
source text. Only whitespace runs are normalized; case/punctuation remain exact.
No fuzzy matching. Reject malformed output, refusal, missing choices/content,
truncation (`finish_reason != stop`) and unexpected returned models. Source
membership and quote matching do not prove the observation's truth or entailment.
Evidence is explicitly treated as untrusted data in the prompt.

## Errors and metadata

| Failure | Code | Retry candidate for a future worker |
| --- | --- | --- |
| Missing/invalid AI settings | `configuration` | No |
| Bad evidence/count/size; HTTP 400/404/413/422 and other ordinary 4xx | `invalid_request` | No |
| HTTP 401/403 | `provider_auth` | No |
| HTTP 429 | `rate_limited` | Yes, consider Retry-After |
| SDK timeout, deadline, HTTP 408 | `timeout` | Yes |
| SDK connection error | `network` | Yes |
| HTTP 409 | `provider_transient` | Yes |
| HTTP 5xx | `provider_server` | Yes |
| Other provider errors | `provider_failure` | No automatic classification |
| Malformed/refused/truncated output, schema/evidence/model mismatch | `invalid_output` | No blind retry |

The analyzer never retries. Safe errors carry code, retryability, parsed
Retry-After where available, and metadata where available. No provider body or
raw SDK exception is attached. Cancellation propagates to the caller.
Timeouts can still consume provider quota.

Metadata includes configured/returned model, completion/request IDs when supplied,
prompt/schema versions, input/completion usage (missing is null), finish reason,
latency and validation outcome. Nothing is persisted. SDK request/response debug
logging is suppressed because it includes private payloads; do not override this
or log Evidence/results/HTTP bodies or keys in calling code.

## Validation and live smoke

Deterministic tests use the real SDK with `httpx.MockTransport`, without network
calls. Full backend tests additionally verify auth/RLS and Notes with invalid AI
configuration and no key.

After configuring `GROQ_API_KEY` in the shell environment or ignored `backend/.env`,
run from `backend/` with your backend virtualenv activated:

```sh
python scripts/smoke_groq_text_analysis.py --live
```

Requires the backend dependencies in the active Python environment; no editable
installation or manual PYTHONPATH is needed. The script resolves `app` relative
to its own checkout. Exactly one synthetic short source, one 20B request, no
retries. Only safe metadata and the synthetic structured observations are printed. Without `--live`
it refuses to run; without a configured key it exits 2 without a request. Shell variables take
precedence over `backend/.env`.
The script is not part of pytest or CI. Never put the key in the command itself.

Remaining limits: no quota accounting, scheduling, persistence, source loading,
quality/entailment judge or public entry point. Account limits, region reachability
and provider data-retention settings must be reviewed before product wiring.

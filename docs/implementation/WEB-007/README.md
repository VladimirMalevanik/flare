# WEB-007 — ручная отправка писем

В Settings добавлено окно с адресатами, темой и текстом. Кнопка появляется после
серверной проверки доступа. Получатели получают отдельные копии и не видят чужих
адресов. Автоматических цепочек, повторных отправок по таймеру и чтения ответов нет.

## Доступ

Участники определены владельцем в текущем чате: шесть аккаунтов. Их личные адреса
не публикуются в репозитории, описании PR или клиентском коде.

Вова / владелец релиза задаёт только в серверном окружении API переменную
`DEVELOPER_MAIL_ACCOUNTS`: JSON-объект из пар `auth:<UUID пользователя>` →
`подтверждённая почта этого пользователя`. Максимум шесть записей. Пустая или
неверная конфигурация закрывает доступ всем. Пользователь должен войти в свой
аккаунт, иметь подтверждённую почту и принять действующие условия сайта.

Перед включением владелец сопоставляет предоставленные ему шесть адресов с
существующими `auth_users.id`, проверяет владение каждым аккаунтом и записывает
соответствие в приватной конфигурации. Автоматическая отметка `bypassed` в
`verification_provenance` не доказывает владение почтой: такие аккаунты требуют
отдельного подтверждения владельцем доступа. Новый аккаунт с тем же адресом после
удаления старого не получает право автоматически — его ID будет другим.

Роль owner в обычном workspace права на почту не даёт. Разрешённый разработчик
может иметь роль viewer: право относится к аккаунту, а не к содержимому workspace.
Capability возвращает только разрешение текущего пользователя, готовность SMTP и
адрес отправителя. Список участников и настройки SMTP в ответ не входят.

## Отправка

Используются существующие `SMTP_URL` и `EMAIL_FROM` из настроек API. `EMAIL_FROM`
должен быть одним обычным адресом, подтверждённым провайдером. SMTP-секрет остаётся
в существующем серверном механизме хранения. Если SMTP не настроен, форма сообщает
об этом и отключает отправку. Локальная печать в журнал не считается отправкой.

API: `GET /ops/mail/capability`, `POST /ops/mail/send`; на сайте — через `/api`.
POST принимает `recipients` (1–20 адресов), `subject` (до 200 символов) и `body`
(до 20 000 символов). Отправитель не задаётся клиентом. Заголовки в адресах и теме,
дубликаты адресатов и неизвестные поля отклоняются. Письмо отправляется как текст.
На запрос одновременно работают максимум четыре SMTP-соединения; каждое использует
существующий таймаут сокета 10 секунд и проверку TLS. Это не абсолютный срок всей
отправки: SMTP проходит несколько сетевых этапов. Клиент ждёт ответ до 90 секунд.

Результат по каждому адресу:

- `accepted`: провайдер принял письмо; это ещё не подтверждает попадание во входящие.
- `failed`: SMTP явно отклонил письмо; можно вручную повторить только эти адреса.
- `unknown`: ответ потерян или результат нельзя подтвердить. Повтор для этого
  письма блокируется; сначала нужно проверить провайдера или получателя.

Повторное нажатие во время запроса заблокировано. При потере соединения автоматического
повтора нет. Черновик сохраняется в памяти окна при закрытии, не пишется в браузерное
хранилище и сбрасывается при смене аккаунта или уходе со страницы. После результата
поля остаются неизменными до выбора «New email». Истории писем и вложений пока нет.

## Выпуск и проверка доставки

Реализация не включает настройку провайдера, DNS или публикацию на рабочем сайте.
Вова координирует выпуск с активной OPS-005, задаёт приватные разрешения и SMTP,
после чего проверяет кнопку у разрешённых аккаунтов и отсутствие доступа у обычного
пользователя, включая прямой POST. Сначала отправляется одно тестовое письмо на
адрес владельца, согласованный в чате. По полученному письму проверяются From,
SPF, DKIM и DMARC; затем отдельно проверяется канал для ответов на адрес отправителя.

Неудачная предыдущая проверка через resend-verification не доказывает отказ SMTP:
этот endpoint не отправляет письмо уже подтверждённому аккаунту и возвращает
нейтральный ответ. Gmail в Arc открывался пустой страницей, а управление вкладкой
завершалось по таймауту; получение письма этой работой не подтверждено.

Изменения не затрагивают main/config/database и активные области OPS-005 / API-005.
Для полного выпуска потребуются принятый PR, приватная настройка и проверка реального
письма. Задача остаётся review до фактической приёмки.

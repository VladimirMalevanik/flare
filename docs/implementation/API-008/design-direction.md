# Team shared-context correction

Owner brief: Team collects members' notes in one project and produces shared Flares. It is not a task manager. Preserve individual accounts and private personal projects.

Reference lock: existing Flare Vault note rows/cards and current Team membership dialogs. Retain the current white/dark canvas, blue action role, typography, bordered surfaces, spacing and keyboard-safe custom Select/Dialog. Refero craft reference: semantic navigation, URL project state, readable form spacing, inline errors and real asynchronous statuses. No new visual language or decorative assets.

| Decision | Evidence | Role |
| --- | --- | --- |
| Shared notes are the default Team view | Owner correction + existing Vault | Context storage, not task tracking |
| Capture and Vault remain the single note editing path | Existing Flare product | Avoid a second note model or duplicated editor |
| Flares and Sources link to the same explicit project | Owner + existing per-tab routing | One shared context/analysis boundary |
| Membership lives in a secondary view | Existing Team permissions | Keep invitations and roles without displacing notes |
| Show real server-authored note creator | Existing Vault metadata pattern | Preserve creator across a colleague's edit; never infer historical authors |
| Retain scheduled workspace analysis and quota | Existing accepted contract | No per-person fan-out or automatic provider burst |

Existing legacy task storage is preserved for compatibility; no task requests, controls or task usage are part of the new Team interface. Personal notes are never automatically copied into Team.

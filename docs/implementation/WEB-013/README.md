# WEB-013 — закрытый импорт возвращался после обновления

Пользователь20 октября2026 сообщил: Close import скрывает failed flare-notes.zip,
но после обновления Sources та же ошибка появляется снова.

Причина: resetResult очищал только состояние компонента, а при монтировании
listImportPackages безусловно восстанавливал последний receipt данного источника.
Регрессионный тест с новым экземпляром страницы воспроизвёл ошибку для Notion
и Obsidian на исходном коде до исправления.

## Изменение

- Close import и Choose another ZIP сохраняют закрытие terminal receipt в
  localStorage. После reload и перехода на Sources тот же результат не открывается.
- Ключ включает ID аутентифицированного пользователя, ID выбранной рабочей области
  из AuthSession и тип источника. Другой аккаунт/Team-проект/источник независимы.
  Keyed child сбрасывает состояние и отменяет запросы при смене этого контекста.
- Сохраняется только fingerprint ID попытки, ID canonical result, статуса, фазы,
  кода ошибки и счётчиков. Имена файлов, заметки, email и токены не сохраняются.
  На один контекст хранится один fingerprint, без накопления списка истории.
- Отличаем новую попытку от старого canonical result при дедупликации одного ZIP:
  новый request ID остаётся видимым даже при том же canonical ID.
- Активный статус никогда не скрывается предпочтением. Новый пакет или изменённый
  отображаемый terminal result также виден. После закрытия последнего результата
  не подставляется более старый пакет из истории.
- Закрытие не вызывает API-записи, удаления, отмены или нового импорта. Серверная
  история, заметки и обработка остаются прежними. Исходный сбой ZIP этим изменением
  не диагностируется: это исправление поведения закрытия уведомления.
- Если браузер блокирует/переполняет localStorage, карточка закрывается на эту
  страницу и показывается понятное сообщение на английском/испанском. Исключение
  хранилища не ломает приложение. При отсутствии identity общих предпочтений нет.

Закрытие действует в данном браузере. Очистка браузерных данных или другой браузер
могут снова показать серверный receipt; синхронизации dismiss в БД не добавлено.
Серверный контракт импортов, зависимости и защищённая задача API-005 не менялись.

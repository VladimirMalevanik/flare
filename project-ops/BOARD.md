# Состояния задач

| Состояние | Файл | Смысл |
|---|---|---|
| next | work/NEXT.md | Можно начать после завершения зависимостей |
| active | work/ACTIVE.md | Назначена конкретному исполнителю |
| review | work/REVIEW.md | Результат ожидает проверки |
| waiting | work/WAITING.md | Есть блокирующее условие |
| paused | work/BACKLOG.md, раздел «Пауза» | Работа приостановлена |
| backlog | work/BACKLOG.md, раздел «Зарегистрированные улучшения» | Будущая работа |
| done | work/archive/YYYY-QN.md, раздел «Готово» | Проверенный и принятый результат |
| cancelled | work/archive/YYYY-QN.md, раздел «Отменено» | Работа отменена |

Один ID находится ровно в одном состоянии, включая архив. Переходы выполняются
через CLI, без ручного редактирования таблиц. Зависимость разблокируется только
состоянием `done`; `cancelled` не означает выполненную зависимость.

`NOW.md` хранит ближайшую цель и критерии; `QUESTIONS.md` — вопросы человеку.
`STATUS.md` генерируется из них и файлов состояния. Изменили цель или вопросы —
выполните `task-sync render-status`, затем `task-sync verify-snapshot` и опубликуйте
документы вместе обычным процессом проекта.

Назначение: `claim`; обновление без перехода: `update`; переход: `move`.
Команда `correct-expected` меняет результат только ещё не назначенной задачи
в `backlog`, `next`, `paused` или `waiting` и записывает причину в журнал.
Архив и журнал месяца создаются автоматически при необходимости.
